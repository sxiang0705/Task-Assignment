# Renew Curve v9 驗證目標

文件狀態：初版驗證基準。

需求來源：[v9 專案規格與畫面流程](./v9%20專案規格與畫面流程.md)

開發流程：[v9 開發流程](./v9%20開發流程.md)

## 1. 文件目的

本文件將 Renew Curve v9 規格轉換成可觀察、可重現、可持續檢查的驗證目標。開發者應在開始功能前、完成小幅修改後、結束里程碑時及發布前翻閱本文件，用來校準實作是否仍符合原始需求。

本文件不是一次性的最終驗收表，也不是測試結果的宣傳紀錄。任何項目只有在符合明確通過條件並留下證據後，才能標記為通過。

## 2. 驗證文件使用規則

- 每個目標使用固定且不可重複的 `VAL-*` ID。
- 開發工作、測試名稱、問題紀錄及提交說明應引用相關 ID。
- 規格改變時，先修改規格，再修改此文件的通過條件，最後修改程式與測試。
- 不因目前實作做不到而降低驗證條件；若確認調整需求，必須回到規格文件處理。
- 自動化測試通過不等於 GUI、打包及真實 Gmail 驗收自動通過。
- 手動驗證不得只填「看起來正常」，必須記錄環境、操作及結果。
- 涉及資料破壞的匯入、刪除及還原測試，只能在測試資料目錄或乾淨驗收環境執行。
- 證據不得包含 OAuth token、密碼、真實任務內容或其他敏感資料。

## 4. 優先級

| 等級 | 定義 | 處理規則 |
|---|---|---|
| P0 | 資料安全、認證安全、核心排程與不可違反的業務規則 | 失敗時停止擴大相關功能，不得發布 |
| P1 | 使用者完成主要流程所需的功能與可用性 | 里程碑結束前必須通過，不得帶入發布版 |
| P2 | 不阻斷主要流程的視覺、便利性與次要品質 | 可排程修正，但必須記錄原因與期限 |

## 5. 驗證狀態

| 狀態 | 定義 |
|---|---|
| `NOT_RUN` | 尚未執行，不能視為通過 |
| `PASS` | 已依指定方式執行，符合通過條件且有證據 |
| `FAIL` | 已執行但不符合通過條件 |
| `BLOCKED` | 缺少外部帳號、乾淨 Windows 或其他必要條件，且已記錄原因 |
| `N/A` | 經規格確認不適用，必須附上理由 |

測試失敗必須標為 `FAIL`，不可用 `BLOCKED` 隱藏失敗。

## 6. 驗證方式與執行時機

### 6.1 驗證方式

| 縮寫 | 方式 |
|---|---|
| U | 純 Domain 或工具函式單元測試 |
| I | SQLite、檔案、Service 或跨模組整合測試 |
| G | pytest-qt 或等效 GUI 自動化測試 |
| S | 安全與惡意輸入測試 |
| M | 人工操作驗收 |
| P | PyInstaller／乾淨 Windows 打包驗收 |
| R | 使用真實 Gmail 測試帳號的驗收 |

### 6.2 執行時機

| 縮寫 | 時機 |
|---|---|
| C | 修改相關程式碼後 |
| F | 功能完成時 |
| M | 里程碑結束時 |
| RC | 發布候選版 |

例如 `U/C` 表示每次修改相關核心程式碼後都執行單元測試；`R/M,RC` 表示里程碑與發布候選版使用真實帳號驗證。

## 7. 證據標準

### 7.1 自動化證據

- 測試名稱或 docstring 應包含對應 `VAL-*` ID。
- 記錄執行指令、日期、程式版本或 commit、通過／失敗數及輸出檔位置。
- 效能測試必須同時記錄資料量與機器規格。
- 測試不得依賴先前測試留下的資料或真實使用者 AppData。

### 7.2 手動與 GUI 證據

- 記錄 Windows 版本、解析度、縮放比例與操作步驟。
- 視需要保存截圖，但截圖應遮蔽郵件地址及任務內容。
- 錯誤流程應同時記錄畫面訊息與 log 中的非敏感診斷資訊。

### 7.3 Gmail 證據

- 使用專用測試帳號，不使用開發者主要信箱。
- 只記錄成功／失敗、時間、測試信件 ID 的遮蔽版本與應用程式狀態。
- 不保存 token、完整郵件本文或附件內的真實內容。

## 8. 校準 Gate

### Gate A：修改完成

- 受影響的 U、I、G 或 S 測試通過。
- 變更影響對照中的相依範圍已檢查。
- 沒有新增 P0 失敗。

### Gate B：功能完成

- 該功能所有 P0、P1 驗證通過。
- 正常、邊界、取消及失敗流程都有證據。
- UI、Service、Domain、Infrastructure 的責任沒有互相穿透。

### Gate C：里程碑完成

- 完整 pytest 通過。
- 該里程碑所有手動驗收完成。
- P0、P1 沒有 `NOT_RUN`、`FAIL` 或未說明的 `BLOCKED`。
- 校準摘要與執行紀錄已更新。

### Gate D：可發布

- 所有 P0、P1 驗證均為 `PASS`。
- 適用的 P2 已通過，或有明確接受紀錄。
- 效能、GUI 尺寸／DPI、完整備份還原、真實 Gmail 及乾淨 Windows 打包驗收通過。
- 成品不含 token、真實資料、開發路徑或測試入口。

## 9. 參考驗證環境

### 9.1 功能環境

- Windows 10 x64 與 Windows 11 x64。
- Python 3.10 以上的開發環境。
- PyInstaller 成品驗證環境不安裝 Python。
- 所有日期測試使用可注入 clock，不依賴執行測試當下的真實時間。
- 所有檔案測試使用 pytest 暫存資料夾或等效隔離目錄。

### 9.2 GUI 矩陣

| 解析度 | 縮放比例 |
|---|---|
| 1280×720 | 100%、150% |
| 1920×1080 | 100%、150%、200% |

通過條件不是像素完全相同，而是文字可讀、主要按鈕可見、內容可捲動、焦點順序合理，且沒有阻斷操作的重疊或裁切。

### 9.3 效能資料集

- 5,000 個任務。
- 50,000 筆複習排程。
- 任務應混合未開始、進行中、今日、逾期、完成、未完全完成、暫停及封存狀態。
- 至少包含 100 個分類、500 個標籤，以及足以測試搜尋的中英文名稱與說明。
- 使用固定 seed 產生，可重複建立完全相同的資料。

### 9.4 效能參考機器

- Windows x64。
- 至少 4 個邏輯 CPU 核心。
- 8 GB RAM。
- SSD 儲存。
- 測試時記錄 CPU、RAM、Windows 版本及是否為 VM。
